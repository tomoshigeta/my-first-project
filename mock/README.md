# 資産可視化ダッシュボード — 画面構成モック

grilling（全35問）で決めた仕様を、実際に見て確かめるためのモックです。
**実装ではなく画面構成の検討用**なので、外部ライブラリ・API・ビルドは一切使いません。

## 開き方

`index.html` をブラウザでダブルクリックするだけです（サーバ不要）。
最初はサンプル（`data.js`）が表示されます。

自分のデータを映すには、左下の **「JSONファイルを読み込む」** から JSON ファイルを選びます。
JSON の書き方と手順は [`../data/README.md`](../data/README.md)、ひな形は
[`../data/template.json`](../data/template.json) です。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | ① サマリー — 金融資産と総負債を並置 |
| `realestate.html` | ② 不動産 — 物件別の投資構成と月次収支 |
| `accounts.html` | ③ 資産・負債明細 — 有価証券・預貯金・負債 |
| `data.js` | サンプルデータ。形式は `../data/template.json` と同一 |
| `app.js` | 集計・整形・描画の共通ロジック |
| `styles.css` | 配色トークンとレイアウト |

## データの不変条件

`data.js` と読み込む JSON の両方に当てはまります。壊すと画面が合わなくなります。

- 期間を持つ金額（収支・返済）はすべて **月額**
- 固定資産税は **年額 ÷ 12** の平均月額（`propertyTaxMonthly`）
- `securities` のみ元通貨で保持し、`rates` で円換算
- `totalInvestment = ownFunds + loan.principal`
- `loan.principal = loan.balance + loan.cumulativeRepaid`

読み込み時に `app.js` の `validateData` がこの不変条件と項目の型を検査し、
合わなければ読み込まずに「どこをどう直すか」を右下に表示します。

## JSON の読み込みの仕組み

`file://` で開いたページは `fetch` で隣の `.json` を読めない（CORS）ため、
`<input type="file">` でユーザーにファイルを選んでもらい、`FileReader` で読みます。
読めた JSON は `localStorage`（キー `assetDashboard.json`）に控えを置き、
3ページの移動と再読み込みをまたいで同じデータを表示します。

- 控えはあくまでキャッシュで、**正は手元の JSON ファイル**（仕様: 手書きの単一ファイルが正）
- 「サンプルに戻す」で控えを消し、`data.js` に戻る
- 控えが壊れていれば黙って捨て、`data.js` に戻る

サンプルの `data.js` は、`window.ASSET_DATA = ` の右辺が JSON と同じ形です。
ローカルサーバで配信する段階になれば、そのまま `fetch` に置き換えられます。

## 色のルール

> **塗られた面 = 何であるか。文字の色 = 良いか悪いか。**

面（棒の塗り）に使う色は3つだけで、意味は3ページ共通です。

| 色 | 意味 | Light | Dark |
|---|---|---|---|
| 緑 | 自分の持ち分（自己資金・評価額・預金残高） | `#059669` | `#0ea472` |
| 紫 | 返済済み（借入のうち返し終わった分） | `#4a3aa7` | `#9085e9` |
| 青 | 負債（残債） | `#3b82f6` | `#2b6fc0` |

損益は日本式（赤＝益、青＝損）で、**文字と斜めハッチ**の両方に使います。

| | 表記 | 文字 Light / Dark | ハッチ Light / Dark |
|---|---|---|---|
| 含み益 | `+1,234` | `#c62828` / `#f87171` | `#c62828` / `#d64545` |
| 含み損 | `▲1,234` | `#1c5cab` / `#6da7ec` | `#1c5cab` / `#4d97ee` |

`▲` は会計慣行どおりマイナスを表します。

損益を面にも塗るため、**形でも区別できるようにしています**。

> **ベタ塗り ＝ 元本・カテゴリ ／ 斜めハッチ ＝ 損益**

これは装飾ではなく必須です。検証の結果、①赤と緑の隣接はダークで ΔE 6.3（要注意帯）
②含み損の青と残債の青はダークで判別不能（ΔE 12.8、下限15）でした。
ハッチという色に依存しない 2つ目の手がかりがあって初めて成立しています。
**ハッチを外すと色覚多様性とダークモードで読めなくなります。**

3色は colorblind 安全性・明度帯・彩度・コントラストを機械検証済みです。
当初案のグレー `#E5E7EB` は彩度とコントラストで不合格だったため紫に差し替えました。
**色を変えるときは必ず再検証してください。**

## 棒グラフの基準

3ページとも棒は**テーブルの最右列・固定幅264px**に置いています。テーブルの外枠幅が
同じなので、③ の3セクションでは棒の左端・右端が縦に揃います（画面幅 1280px 以上）。
それより狭いときは各テーブルが自分の中で横スクロールします。

基準（トラック全体が何を表すか）はセクションごとに違うため、**列見出しに明記**しています。

| セクション | 棒 | トラック全体＝100% |
|---|---|---|
| 有価証券 | 元本＋含み損益 | 最大クラスの `max(取得原価, 評価額)` |
| 預貯金 | 残高 | 預貯金合計 → **棒の長さがそのまま構成比** |
| 負債 | 返済済み＋残債 | **その行の当初借入額**（どの行も全長が同じ） |

有価証券の棒は、緑が「元本のうち失われていない部分」です。

- **含み益**: `[緑 取得原価][赤ハッチ 含み益]` → 棒の全長 ＝ 評価額
- **含み損**: `[緑 評価額 ][青ハッチ 含み損]` → 棒の全長 ＝ 取得原価

負債の棒はどの行も全長が同じで、返済の進み具合だけを横並びで比較します。
ローンの規模差は棒からは読めないので、`当初借入額` の列で読みます。

預貯金だけ合計基準なのは、棒（最大値基準）と構成比（合計基準）が同じ行に並ぶと
分母が2つになって読めなくなるためです。有価証券と負債は「項目間の大小比較」が
目的なので最大値基準を保っています。

## 意図的に入れていないもの

| 項目 | 理由 |
|---|---|
| 不動産の時価・含み益 | 時価が確定できないため（含み益は有価証券のみ） |
| 総資産（不動産＋金融の合算） | 不動産に金額がないため合算不能 |
| 純資産（資産 − 負債） | 資産に不動産を含めず負債だけ含めると実態より小さく出るため |
| LTV | 分母の物件価値がないため計算不能。返済進捗率に置き換え |
| 利回り | 計算はできるが、棚卸しという目的から外れるため非表示 |
| 履歴・前回比 | 見たいのは含み益であって前回比ではないため |
| 円グラフ | 金額の読み取りに不向き。横棒に統一 |

有価証券の資産クラスは **株 / 債券 / 投資信託 / その他** の4種類のみです。
暗号資産・金・銀などの現物資産は「その他」にまとめます。国内・海外とも
4行を常に表示し、残高ゼロでも行は消しません（入れ忘れに気づけるように）。

「物件追加」ボタンは将来のアプリ化用のプレースホルダで、`disabled` にしています。
